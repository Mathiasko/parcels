# Parcels Mac App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `Parcels.app`, an unsigned, menu-bar Electron app that runs the existing server and poller in a utility process. It moves an existing git install in, and updates itself from GitHub Releases.

**Architecture:**
- The Electron main process (`app/`) owns the tray, window, notifications, login item, first run, move-in and swap-and-relaunch.
- `src/app-server.ts` runs `buildServer()` plus an in-process poll schedule in an Electron `utilityProcess`. It talks to main only through typed `parentPort` messages.
- Everything Mac-install-specific in `src/` (notifier, updater, support bundle, wording) gets a `host() === 'app'` branch behind its existing seam.

**Tech Stack:** Electron 45.1.0 (Node 24.22.1), electron-builder 26.18.0, TypeScript (nodenext ESM), fastify, better-sqlite3 13, luxon, vitest.

**Spec:** `docs/superpowers/specs/2026-10-29-mac-app-design.md`. Read it first; section numbers below (§) refer to it.

## Global Constraints

- **Repo files that must never be touched:** never read, print, modify or commit the repo's own `config.json` or `data/`, which hold the live data and the Gmail App Password. Never use `git add -A`, `git add .` or `git commit -a`; add files by name.
- **No test may touch the real machine:**
  - no `launchctl`, `codesign`, `osascript`, `open` or network;
  - nothing in `~/Library`.
  - Every such effect goes through an injected function, and tests pass fakes or temporary directories.
- **No agent may run against the live install or real apps:**
  - no `osascript` against Calendar;
  - no `launchctl bootout` of `local.parcels.*`;
  - no move-in against the real install;
  - no writing to `/Applications/Parcels.app`. The spike in Task 1 uses `/Applications/ParcelsSpike.app` only.
- **The git install must stay byte-for-byte the same in behaviour:**
  - all 1465 existing vitest tests keep passing;
  - `bash test/setup.test.sh` and `bash test/update-run.test.sh` keep passing.
- **Node:** the toolchain node is `$HOME/.nvm/versions/node/v24.21.0/bin/node`. Bare `node` and `npm` are nvm lazy-load shell functions that swallow the first call.
  - Run tests as `$N/node node_modules/.bin/vitest run <file>`, with `N=$HOME/.nvm/versions/node/v24.21.0/bin`.
- **Versions:** Electron is pinned to exactly `45.1.0` and electron-builder to `26.18.0`. Electron's Node (24.22.1) meets `engines.node >=24`.
- **Paths (§3):**
  - support folder: `~/Library/Application Support/Parcels/`;
  - logs: `~/Library/Logs/Parcels/`;
  - config: `<support>/config.json`, mode 0600;
  - data: `<support>/data/`, with `dbPath` the relative `data/parcels.db`.
- **Environment the app sets for the server process:** `PARCELS_HOST=app`, `PARCELS_CONFIG`, `PARCELS_APP_VERSION`, `PARCELS_APP_BUNDLE`, `PARCELS_LOG_DIR`.
- **GitHub:** the repo is `Mathiasko/parcels`. The release asset names are exact: `Parcels-<v>-arm64.zip`, `Parcels-<v>-x64.zip`, `Parcels-<v>-arm64.dmg`, `Parcels-<v>-x64.dmg`, `SHA256SUMS`.
- **Signing identity:** "Parcels Signing". Its leaf-certificate SHA-256 is committed in `app/signing-cert.sha256`.
- **Poll slots (§2.2):** 07:00 through 21:00 on the hour, plus 15:30, in the Mac's local time zone.
- **Server process exit codes:** port in use → 3.
- **Pages:** no JavaScript anywhere. The dashboard's CSP stays as it is, and the welcome and move-in pages follow the same rule.
- **Wording:** user-facing copy follows `docs/design-language.md`: plain sentences, and what to do next.
- **Commits:** each ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Before any push, leak-check the diff for emails, tracking numbers and pickup codes.

## Review Focus

1. **Port 8787 already taken.** The old launchd web job is still running (the user picked "Not now" once, or a move-in rolled back). The app must show one dialog naming the port and the fix, and must not restart in a loop. → Task 5 (exit code 3), Task 8 (supervisor stops on 3).
2. **An update that fails halfway.** The cases: a 403 rate limit from GitHub, a truncated download, a `SHA256SUMS` without a line for the asset, or a zip that unpacks to no `Parcels.app`. Each must leave no staging folder behind, show the reason, and keep the running app untouched. → Task 6.
3. **Daylight saving and sleep.** On the night the clocks change, the next slot is still the right wall-clock time. After a Mac sleeps through 09:00–14:00, it polls exactly once on wake, not five times. → Task 2.
4. **An old install that is half there.** The plist points at a clone folder that was deleted. Or the clone has no `data/tiles`, no `dpd-auth.json`, or an absolute `dbPath`. Move-in copies what exists and never fails on what is absent; a deleted clone gets the Welcome page. → Task 9.
5. **Quit or log out during a poll.** Shutdown waits for the run (fastify `onClose` already awaits `refreshIdle`) up to 5 s, then kills it. The next start reaps the open run row rather than showing it as running forever. → Task 5 (shutdown waits), Task 8 (5 s kill).

  ```ts
  interface AppHostDeps {
    configPath: string; post: (m: ToMain) => void; now?: () => Date
    setTimer?: (fn: () => void, ms: number) => { clear(): void }
    poll?: (db: Database, config: Config) => Promise<{ ran: boolean }>  // defaults to runPollOnce
  ```

  ```ts
  export const RELEASES_URL = 'https://api.github.com/repos/Mathiasko/parcels/releases/latest'
  export function compareVersions(a: string, b: string): -1 | 0 | 1     // "0.10.0" > "0.9.1"; a leading "v" ignored
  export async function checkAppRelease(current: string, fetchJson: (url: string) => Promise<unknown>, url = RELEASES_URL): Promise<UpdateCheck>
  //   newer → { state:'behind', behind:1, changes:<non-empty lines of body, max CHANGES_SHOWN>, version:<tag w/o v>, upstream:'GitHub Releases' }
  //   same/older → 'current'; network/HTTP/shape problem → 'blocked' with a one-sentence reason (403 → "GitHub refused the check (rate limit); it is retried tomorrow.")

    | { state: 'downloading'; version: string; startedAt: Date }

    | { state: 'failed'; version: string; reason: string; startedAt: Date; finishedAt: Date }
    | { state: 'installed'; version: string; finishedAt: Date }   // written by the app host at startup when a staged version equals the running one
  export const appUpdateStatusPath = (supportDir: string) => join(supportDir, 'updates', 'status.json')
  export function readAppUpdateStatus(path: string): AppUpdateStatus | undefined   // never throws
  export interface StageDeps {
    version: string; arch: 'arm64' | 'x64'; appBundle: string; supportDir: string
    download: (url: string, dest: string) => Promise<void>
    run: (cmd: string, args: string[]) => Promise<{ code: number; stdout: string }>   // ditto, codesign
    expectedCertSha: string                                                         // from app/signing-cert.sha256, bundled
    releaseBase?: string   // default `https://github.com/Mathiasko/parcels/releases/download/v<version>`
  }
  export async function stageUpdate(d: StageDeps): Promise<AppUpdateStatus>    // writes status as it goes
  ```
  `stageUpdate` runs these steps in order, each failure being `failed` with a reason, and the staging folder `<dirname(appBundle)>/.Parcels-update-<v>` removed:

  2. compare SHA-256 (`node:crypto`, streamed);
  3. `ditto -x -k <zip> <staging>`, then `<staging>/Parcels.app` must exist;
  4. `codesign --verify --deep --strict <staged app>` exits 0;
  5. the leaf certificate SHA-256 of the staged app equals `expectedCertSha`. Extract it with `codesign -d --extract-certificates=<tmp>/c <app>` and hash `<tmp>/c0`.

  The downloads folder is removed on success too.

  `moveIn` does these, in order:
  1. Runs `bootout gui/<uid>/<label>` for each label. A non-zero exit whose stderr says the service is not loaded (exit 3 or "No such process") counts as success.
  2. `mkdir` the support folder at 0700 and `data/` at 0700.

  5. Writes `config.json` (0600) from the clone's document, with `dbPath` set to `data/parcels.db` when it was absolute.
  6. Opens the copy and requires `PRAGMA integrity_check` to equal `ok`, and requires `loadConfig` of the copied config to succeed.
  7. Moves each plist into `<clone>/launchd-backup/`.

  A failure at any step before 7 removes the support folder, runs `bootstrap gui/<uid> <plist>` for each, and returns `ok: false` with the step.

  - `swapScript(p: { pid: number; app: string; staged: string; version: string; marker: string }): string`: a POSIX `sh` script, with every path single-quoted and escaped. The algorithm:

    ```sh
    while kill -0 $pid 2>/dev/null; do sleep 0.2; done

    ```
